## The two that are not NullPointerUse

Everything above except these is either the HiiDatabase pointer-overflow set (nine sites,
confirmed by reading the source: `ExportPackageList` computes `(UINT8 *)Buffer + ResultSize`
on the size-query pass, where its own guard permits `Buffer == NULL`) or a `NullPointerUse`
from the harness handing NULL to a parameter the spec does not mark OPTIONAL.

These two are real sanitizer reports on a `CopyMem`, and want triage:

| protocol | module | class | access | size | hits |
|---|---|---|---|---|---|
| EfiDevicePathUtilities | DevicePathDxe.efi | heap-buffer-overflow | read | 0x5F7D (24445) | 7 |
| EfiFirmwareVolumeBlock | DxeCore.efi | unknown-crash | write | 0xF20F (61967) | 4 |

The shadow around the DevicePath one shows the source starting on a byte with shadow `04`
-- four valid bytes -- inside a run of `FA` redzone, so the copy begins at the edge of an
allocation and runs 24KB past it.

**Both are the harness, and both are now traced to a specific defect.** Neither is a
firmware bug.

*DevicePathUtilities.* The harness allocates a 4 byte `EFI_DEVICE_PATH_PROTOCOL`, writes a
valid END node into it, and then overwrites the node's own length:

    ReadBytes(Input, sizeof(ChooseFile_Arg_0->Length), (VOID *)&(ChooseFile_Arg_0->Length));

`0x5F7D` is 24445, which is exactly the reported copy size -- the out of bounds read *is*
the fuzzed `Length` field, on a four byte allocation. Malformed device paths are a real
attack surface, because `Boot####` variables are not under firmware control, so this is
worth reaching deliberately rather than by accident; it is not evidence of a defect in
`DevicePathDxe`.

*FirmwareVolumeBlock.* `fuzzable_args` does bound the size by the buffer --
`*Write_Arg_3 = *Write_Arg_3 % (4096 + 1)` -- and then the live value substitution that
runs afterwards replaced the whole `UINTN *` with one drawn from an earlier call's output,
which had never been clamped, while the data buffer stayed 4096 bytes. `0xF20F` is 61967.
The clamp was real and the substitution silently undid it.

Fixed: a size and the buffer it describes are now pinned out of the live tables, since
substituting either half breaks the invariant the clamp establishes. Live threading is
otherwise untouched -- EfiHiiDatabase goes from 60 substitution sites to 48,
EfiDevicePathUtilities 64 to 60, EfiBlockIo2 unchanged; only FVB drops sharply, because
almost every argument it takes is a buffer or a size for one. The regenerated harness
builds with CLANGSAN.
